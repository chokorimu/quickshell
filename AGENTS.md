# AGENTS.md

Desktop dotfiles ecosystem: the Quickshell (QML) Hyprland shell plus Hyprland, matugen and the apps around them. Every top-level directory is a stow package. This is a config repo, not a software project.

## There is no toolchain — do not look for one

- No `package.json`, build system, test runner, linter, formatter, typecheck, CI, pre-commit, or task runner exists. Nothing to "run".
- **Quickshell 0.3.2 is installed** (`qs --version`). The scaffold was written against 1.x, so most API names needed correcting — see the API section below. Verify against the installed version, not the README.
- The only real verification is `qs -p ~/.config/quickshell` (plain `qs` once stow-deployed). QML errors surface on load, so a clean launch is the smoke test.

## Deploying

One stow package per top-level directory; each package contains `.config/<app>/` (or a dotfile at its root). Deploy everything with the installer, or name packages to deploy a subset:

```bash
./install.sh                  # all 11 packages, dry-run + conflict backup first
./install.sh hypr quickshell  # just the named ones
```

- Packages: `quickshell`, `hypr`, `rofi`, `kitty`, `cava`, `btop`, `fastfetch`, `matugen`, `bash`, `zsh`, `OpenTabletDriver`.
- Conflicts (real files) are moved to `~/.dotfiles-backup-<timestamp>/` before stowing. Pre-existing **symlinks** are not backed up — remove them by hand first (that is how the `~/hypr-dotfiles` migration was done).
- Undo a single package with `stow --dir=. --target="$HOME" -D <pkg>`.
- **Never `stow .`** — the repo root is not a package. With 12 package dirs at the root it would try to link all of them straight into `$HOME`. Always name the package (or use `install.sh`).
- GNU Stow 2.4.1 verified. On stow < 2.4.0 the default ignore list drops `README.md`, which would land at `~/README.md` — check `stow --version` before running this elsewhere.

The id lands in a shell command, so it is checked against `/^\d+$/` before use. "No history yet" covers both an empty db and a dead watcher. **The exec-once's `> /dev/null` is load-bearing, not tidiness:** wl-paste infers which MIME type to request from the path of its own stdout (`path_for_fd(STDOUT_FILENO)` → `infer_mime_type_from_name`), and hyprland's stdout is `ly-session.log` — a `text/plain` inference whose `mime_type_is_text` branch tries only text types (no `try_any`), so without the redirect every image copy is silently dropped in watch mode (`offer_destroy; return` — no command spawned, no error, no log line). Proven by A/B: direct form with a `.log` stdout never stores images, `/dev/null` stdout stores all of them. Source: wl-clipboard 2.3.0 `src/wl-paste.c`), step 4 the record row to OBS over obs-websocket — two pills toggle StartRecord/StopRecord and StartStream/StopStream with the elapsed time beside them, and while OBS is offline both pills disappear and a dim "OBS offline" line takes their slot, the bar's ban glyph (`\uF05E`, the network readout's own disconnected mark) beside the text (LO's call: a dead backend has nothing to toggle, and the 5s retry timer already covers the reconnecting the pill's click used to do); the state arrives as `RecordStateChanged` and `StreamStateChanged` events, so a recording or stream started from OBS's own UI or a hotkey shows on the pills too (the record stop event's `outputPath` drives a `notify-send` with the saved file; a stream has no saved file, so its stop event carries nothing to notify with); the two outputs are independent in OBS and tracked independently here — separate `recording`/`streaming` flags, separate counters, and the elapsed slot shows the recording's duration when both are live. The stream pill is the record pill's twin: same shape, same `obsConnected || <live>` visibility rule (so a socket drop mid-stream stays stoppable), same content-driven width, and blue while live (`Theme.cardStream` `#2563eb` with a white label, fixed in both palettes — recording took the palette's red, and one blue reads on both card surfaces; 4.9:1 against white passes AA on the fill); `wf-recorder` is the other candidate backend and is not installed yet). **The OBS client runs over obs-websocket 5.x on `QtWebSockets` (capital S — `qt6-websockets` 6.12.0-1; a throwaway probe verified the path inside quickshell's engine: `import QtWebSockets` resolves, `WebSocket` connects, `sendTextMessage` sends, `textMessageReceived` fires, no `onError` signal exists — watch `statusChanged` + `errorStringChanged` instead). The plugin is at `/usr/lib/obs-plugins/obs-websocket.so` and its server is on with auth off — LO's setting (`server_enabled: true`, `auth_required: false`, port 4455 in `~/.config/obs-studio/plugin_config/obs-websocket/config.json`) — which is the route the client takes because 5.x auth is a SHA256 challenge-response QML's JS cannot compute (the alternative is an `openssl` Process per connect). Protocol: the server sends Hello (op 0) on connect, the client answers Identify (op 1) — the default subscription covers every non-high-volume category, which includes the Outputs events the record state rides on — the server replies Identified (op 2), and from there it is requests (op 6) with responses (op 7) plus pushed events (op 5). The socket lives for the shell's whole life (the page is a persistent instance behind a visible flag, not a Loader), connects at shell start, and retries every 5s while OBS is down — a refused local connect costs nothing, and the pill steps aside for a dim "OBS offline" line until the handshake completes; a rejected request's comment shows in the duration slot for 4s. Verified against a mock obs-websocket server (`/tmp/opencode/obsmock/server.py` speaks the real handshake and answers the three requests) because OBS itself was not running. The CLI route (`obs --startstreaming`/`--startrecording`, stop = terminate) has no state readback, so it is a start button, not a toggle; **a later pass moved the page's layout onto the theme page's idiom without touching any behaviour** — the sections Column rides the content margins both ways (80 left, 28 right) at 4 spacing, each section's label sits in a fixed 120px column with its pills beside it (ThemeCard's control-row, so the two pages read as one system), and the clipboard section reads label → list, the label in the other sections' style (cardForeground at 14, not the dim 12 it started with) with a Reset pill on its right that runs `cliphist wipe` and re-reads the list — the 1px `cardHighlight` hairline that sat under the label is gone, since once the label matched the others the ruler was the one thing left styling the section differently; the list itself rides on a square-cornered `cardHighlight` plate filling the 492×167 slot (LO's call: no rounding, because the dividers run edge to edge and a rounded plate would put their ends on the curve), with a 1px `cardBackground` hairline at each row's foot separating the entries — `cardBackground` rather than `cardHighlight` because on a `cardHighlight` plate a same-token line would be invisible, and the card's own surface cutting through reads as a groove in both palettes; the last row carries no divider (`visible: index < clipList.count - 1` via the delegate's `required property int index`), since a trailing hairline would read as a border the list does not have; the theme page's own controls (the mode switch, the brightness slider) stayed on the theme page — only the layout language crossed over. **A tightening pass after that put every option row on the three control pages (theme, volume, capture) at a uniform 16px gap, at LO's call — 4px was tried first and read as too tight, 8px next, and 16 is where it landed:** theme's Mode↔Brightness 20→16 and Brightness↔wallpaper-grid 16→16, volume's Master↔app-list 8→16 (its rows stay at 4, so the master row keeps a step off the stream list), capture's Screenshot↔Record 20→16 and Record↔clipboard 22→16 — the last one by sizing the clipboard list's slot to 167, since that column is bottom-anchored and exactly children-driven, so the slot is what lifts its top edge. The title→first-option gaps (24/24/20) were left alone: they are header gaps, not between-options ones. The fifth button (door-open glyph, U+F081C — MDI, above the BMP so it ships as the surrogate pair `\uDB82\uDC1C`) opens the session page (`Modules/Bar/SessionCard.qml` — a 160px avatar, click to change through a `FileDialog` that copies the pick to `~/.config/quickshell/avatar.png`, a `user@host` line read from `$USER` and `/proc/sys/kernel/hostname`, and a four-cell power grid — lock / log out / reboot / shut down, via hyprlock, `hyprctl dispatch exit`, `systemctl reboot`, `systemctl poweroff`). The session and theme pages' MouseAreas are click-only: a hover-enabled one inside the card would steal `cardZone`'s hover and collapse the island under a resting cursor. `islandPage` outlives a collapse — the menu holds the last active page through the whole shrink and resets to media only once the card is fully gone (`popOut.onStopped`, guarded on `!expanded` so an interrupted collapse leaves the page alone), so the shrink animates the menu the user was last looking at instead of flashing the default mid-animation; every open either claims its own page (clock, volume icon, tab buttons, SUPER+L) or starts from that default, and `hovered` gates each trigger on the current page so the card stays open while the cursor is on it either way. The block fills the 56px strip, and the pages' content keeps an 80px left margin to clear it; the media page's art, title and transport re-center with `horizontalCenterOffset: cardColumnWidth / 2` so they sit in the content area, not the full card. The expanded strip covers them like it covers the other pages: the cover Rectangle that masks the revealed 56..150px region carries `z: 1` and the tab-button column `z: 2`, so the strip paints over the media content (declared before the cover — without the z the title painted *over* the accordion) while the buttons and their labels stay above it. **The whole column expands on hover.** A `columnZone` MouseArea over the strip (topMargin 28, height cardHeight−28, width tracking `columnWidth`) plus the five buttons feed `columnHovered`, which drives `columnExpand` (0→1, 200ms OutCubic) — the column widens from the resting 56px to `columnExpandedWidth` (150px), revealing each menu's label ("Media" / "Theme" / "Volume" / "Capture" / "Session", title case) beside its glyph. The card never resizes to accommodate it: the expanded column overlays whatever page content sits underneath, and only while the cursor is on the column, so nothing stays covered. The glyphs hold the resting 56px icon zone (`horizontalCenterOffset: -(parent.width - cardColumnWidth) / 2`) so they don't drift as the column opens; the labels live in a `clip: true` Item anchored past `cardColumnWidth` (visible when `columnExpand > 0.01`, opacity tied to `columnExpand`) so they can't spill onto the card mid-animation. Z-order is safe: `columnZone` is declared after the pages (paints above them) but before the buttons (they keep their own hover).
- **The volume card's rows are name / slider / percent — no mute button.** The speaker glyph that sat after the percentage was removed at LO's request; it was also the mute toggle, so per-row mute is gone (mute state still reads as "muted" text, and the bar's volume icon rides the speaker-off glyph tier).
- **SUPER+L opens the island straight on the session page.** hyprland runs `qs ipc call island session`; the rofi powermenu that used to live on SUPER+L moved to SUPER+SHIFT+L. Bar.qml's state: `sessionPinned` (keyboard open), `keyboardDismissed` (latch so the toggle closes under a resting cursor), `expanded = (hovered && !keyboardDismissed) || collapseGrace.running || sessionPinned`. The pin releases the moment the cursor reaches the island (hover handoff), after which ordinary hover rules apply — "hover, then leave" closes it like a hover-opened card. The page outlives the collapse and resets to media once the card is fully gone (see the island bullet). **ESC was tried and dropped:** it needed the always-mapped bar window to take keyboard focus, which meant flipping `WlrLayershell.keyboardFocus` None↔OnDemand with the pin (the enum is the standalone namespace `WlrKeyboardFocus.None`/`WlrKeyboardFocus.OnDemand`, *not* `WlrLayershell.KeyboardFocus.*` — the layer enum works under the attached type, this one does not, and the wrong spelling fails with a TypeError while the binding just stays dead) plus a 50ms `forceActiveFocus` timer so the compositor commits the interactivity change before the activation request. The key never landed — hyprland did not grant the layer focus on the request — so the whole path came back out and the window stays at keyboardFocus None, where it cannot be a focus thief. Close paths are SUPER+L again or hover-then-leave. One `IpcHandler` per target: Quickshell's registry keeps the first registration and warns on duplicates, so with multiple monitors exactly one island answers.
- **The bar's media marquee is a periodic loop, not a ping-pong.** When "Artist - Song" overflows the 180px window, the text renders as three copies separated by `"  •  "` — measured with `TextMetrics` (`baseMetrics` / `unitMetrics`, same font as the text) so the period is exact — and the animation scrolls exactly one period per loop: to the tail (right edge), hold, then the rest of the period, with the loop's `from: 0` snap landing on identical content one period over. Because the loop only ever scrolls within a single period it never runs out of string, which is what makes it infinite with no visible reset. The hold is at the tail only — no hold at the top, no return leg, motion is always right-to-left.
- **The clock flows between the two groups; it is not pinned to the pill's center.** The workspace pill grows ~26px per workspace past the four placeholders (10 workspaces ≈ 264px, ending ~x530 in the 1000px pill), so a clock centered at x500 would start ~x430 and get overlapped. The clock's `x` is therefore clamped: `Math.min(Math.max(centered, workspaceRight + 16), rightRow.x - width - 16)` — centered while the left row is short (identical to the old look up to ~7 workspaces), sliding right only once the pill grows into it, and never into the right row. `root.workspaceRight` (`leftRow.x + workspacePill.x + workspacePill.width`) is the shared left boundary. The hover zone (`clockZone`) follows the text with the same clamping plus a `Math.max(160, Math.min(320, gap - 16))` width — it shrinks toward a 160px floor when the gap between the groups tightens (reachable around 13 workspaces; past that the next step is shrinking `workspaceCircleSize` by count). The old fixed 320px centered zone reached back over the workspace pill and ate clicks on the last circle's right sliver even at four workspaces; the bounded zone fixes that too. Alternatives considered and rejected: shrinking the circles (at 10 workspaces even 16px circles plus a 140px marquee barely fit a centered clock — too much degradation), capping the visible workspaces (loses direct click access), and shrinking the marquee (a 64px window is useless).
- **Circular art is a Canvas arc clip, not a Rectangle clip and not OpacityMask.** `clip: true` on a Rectangle clips children to the item's rectangular bounds — the radius only rounds the Rectangle's own paint — so an Image child renders square (this bit both the bar's 22px art and the card's 200px disc). OpacityMask (`Qt5Compat.GraphicalEffects`) against a circular Rectangle was tried next and **did not clip either** — the art stayed square through a clean reload, no error anywhere. The working approach is the one this repo already proves everywhere else (pill/card/corners): a `Canvas` whose `onPaint` does `ctx.arc` → `ctx.clip` → `drawImage(artSource, 0, 0, width, height)`. The art URL is tracked in a `property url artSource` (Media.artUrl is a QUrl; compare via `.toString().length`), loaded with the async `loadImage()` and repainted on `onImageLoaded`; an empty URL repaints clear so a track without art falls back to the placeholder Rectangle behind the canvas instead of keeping the old art. **The repaint must also fire from `onArtSourceChanged`, not only from `imageLoaded`: `loadImage()` does not re-emit `imageLoaded` for a URL the canvas has already loaded** (verified by probe — fresh URL fires, same URL again does not), so pressing *prev* back to already-seen art would never repaint and the disc would keep the previous track's art while *next* worked. The paint draws straight from the URL through the canvas's pixmap cache, so a cached URL paints immediately and a fresh one completes when `imageLoaded` fires. The card's disc spins clockwise — a `RotationAnimation` on the whole disc, 10s/rev, running while `Media.playing`; a rotating circle is rotation-invariant so only the art moves, and the 0→360 loop snap is invisible because 360 ≡ 0. Qt5Compat is no longer imported at all — the tray tint that needed `ColorOverlay` is gone, since the tray icons now ride in their brand colors inside one shared pill (the workspace pill's surface). The transport row adopts the workspace pill's design outright: a `cardPill` pill — the workspace pill's own surface, the same value as `barWorkspacePill`, one step darker than the card — holding three equal circles, the active one filled in `cardBackground` (the card's surface showing through, the active-workspace treatment) with a `cardForeground` glyph and the inactive two transparent with `cardDim` glyphs like the inactive workspace numbers, FA glyphs F048 / F04B / F04C / F051 (step-backward / play / pause / step-forward — all inside the font's f000–f381 block).
- **The card pops rather than swipes.** One `pop` progress value (0→1) drives the clip's height, the card's horizontal `Scale` (origin top-center), the pill's roll geometry and the window's mask together, so the card grows outward from the top center — height from the bar's bottom edge, width from the center line. `popIn` (300ms, `Easing.Bezier` — a tamed back-ease peaking at ~1.02x) overshoots slightly for the pop; `popOut` (200ms, `OutCubic`) has no undershoot, so the card never dips below zero and mirrors on the way down. The overshoot needs headroom in two places: the clip runs `popOvershoot` (1.12) wider than the card, or the scaled card's side edges get shaved square against the clip, and `windowHeight` carries matching slack, or the window's bounds cut the overshoot off.
- **The media page's background is a cava visualizer.** A `Canvas` declared as the **bottom-most child of the card's content item**, so the lines paint behind the art, the title and the transport pill. It starts past the column strip (`leftMargin: cardColumnWidth + 20`) because that strip is painted by the card canvas *below* the content item — lines reaching under it would paint over the bar's own material. **Thin lines, not bars:** a fixed 2px stem with the gap absorbing the rest (`gap = (w - bw * n) / (n - 1)`), so the row fills the card at any width; in silence the whole row is one unbroken 2px line. Height 300 runs them the full height of the page, behind the disc, the title and the transport pill — that is what makes them read as a backdrop rather than a widget on the card. One Canvas rather than a Repeater of Rectangles: a single paint call per frame instead of 32 binding updates. **The color is `Theme.cardForeground` — the card's own ink** (near-black on the light card, near-white on the dark one) at `globalAlpha` 0.7 (LO's call, up from the 0.5 this shipped with), so the visualizer follows the theme switch instead of sitting on the palette in a fixed accent; it repaints on `cardForegroundChanged` for the same reason the card repaints on `cardBackgroundChanged`. The right margin (24) keeps the stems clear of the card's rounded bottom-right corner — **nothing in the content item is clipped to the card's silhouette** (a Canvas clips only its own paint, and the clip Item is a plain rect), so a line running to the card's right edge would paint onto the wallpaper in the corner. At 24 the last stem's corner lands exactly on the arc's bottom point — tangent to it — which is what lets the lines sit flush to the card's bottom edge with no bottom margin and still not spill. Levels come from `Services/Cava.qml`; the Canvas repaints on that service's `frame()` signal (a JS array is a reference type, so reassigning it notifies but a Canvas still needs an explicit `requestPaint()`), guarded on `visualizer.visible` — cava runs for the shell's whole life now, so a collapsed island would otherwise wake 60 times a second for a backdrop nobody is looking at. Painting is gated on `islandPage === "media"` via the Canvas's `visible`; the process behind it is not gated at all (see the Cava service bullet).
- `Services/` holds the data singletons the bar reads (`AppAudio`, `Audio`, `Brightness`, `Cava`, `Media`, `Battery`, `Network`, `Memory`, `Wallpapers`) plus `Matugen`. See the Services section below — the lazy-initialisation rule there is the thing most likely to bite.
- The other packages' entrypoints: `hypr/.config/hypr/hyprland.lua` (pure-Lua Hyprland config; requires `animations`, `effects`, `keybinds`), `matugen/.config/matugen/config.toml` (palette templates for hypr/rofi/kitty/cava/quickshell), and `rofi`, whose drun the quickshell launcher has replaced (the wallpaper/power menus still use it).

## Theme singleton — the non-obvious part

- `Theme/qmldir` is what registers the singleton (`singleton Theme 1.0 Theme.qml`) and must also declare `Colors 1.0 Colors.qml`. From `shell.qml` you write `import "Theme"`; from `Modules/<Name>/` you need `import "../../Theme"` (see the import section below).
- `Theme.qml` and `Services/Matugen.qml` both use `pragma Singleton` with root type `Singleton` from `import Quickshell`. Follow that shape.
- `Theme/Colors.qml` holds raw hex values (catppuccin-mocha defaults) and is the file matugen is meant to overwrite. Hand-edits there will not survive a palette regeneration.
- **The bar palette deliberately does not live in `Colors.qml`.** `Theme.qml` carries `fixedBar*` constants plus a `barUseMatugen` switch and derived `bar*` properties. `Bar.qml` references only the derived ones, so flipping the bar between the fixed light pill and matugen colors is a one-line change in `Theme.qml`, not a bar rewrite. The light pill is pure white (`#ffffff`) with near-black text — the island card is the lighter-gray surface against it (`fixedCardBgLight` `#f0f0f3`), and the menu column strip takes this same white so the bar's material reads as extending down into the card; check contrast before lightening the text, since a light surface with the old light-gray text is unreadable. A `Theme.darkMode` property (now `readonly`, derived) switches the fixed palette to a deep charcoal pill — the island card takes `fixedCardBgDark` `#2a2a30` with a `card*` content palette that flips per palette (light-on-dark in dark, dark-on-light in light; the transport circles take the opposite of the card surface via `cardInk`/`cardOnInk`), and the tab column's unselected glyphs keep `barDim` since they sit on the bar-colored strip; matugen still wins when `barUseMatugen` is on. **`darkMode` is now derived from `Theme.themeMode`** — the auto/light/dark switch on the island's Theme page (`Modules/Bar/ThemeCard.qml`). `light` and `dark` pin the fixed palette; `auto` follows matugen's generated palette when `barUseMatugen` is on (via `matugenIsDark`, a perceived-brightness split of `_colors.base` at 0.5 — `base` is a hex *string* in Colors.qml, so it goes through a `color` property to get at the channels) and falls back to the dark pill otherwise, which is LO's call. The mode is persisted to `~/.local/state/quickshell/theme-mode` by a `FileView` (see the persistence note below), so the choice survives a reboot. The `//` prefix is back in the bar's left row as pure decoration — it was the TEMPORARY dark-mode toggle until the switch replaced it, and `Theme.darkMode` being readonly means a click there would now throw, so the glyph carries no MouseArea. **The card and the pill are separate surfaces now.** The card (`fixedCardBg*`) is lightened a step above the pill surface (`fixedPill*`, the old card values) so a control sitting on the card can carry its own background and read against it — at the old value the theme-mode switch's track was the same color as the card and invisible. The workspace pill in the bar keeps the darker pill surface, where the inverted language wants it darker than the bar; the theme-mode track takes the same material through `Theme.cardPill`, one step down from the card. The workspace pill takes the pill surface via `barWorkspacePill` (`fixedPill*`) — darker than the bar in the dark palette, where the inverted language wants it — with the active circle taking `barBackground` (lighter than the surface in dark mode, white in light mode) and a `barForeground` number, the one label color that reads on both fills; inactive numbers use `barWorkspaceDim` (the dark palette's muted gray, or a deeper gray that survives on the light surface).
- `Notifications`, `OSD`, and `Session` still hardcode `#1e1e2e` instead of referencing `Theme.barColor`. Replace those with `Theme` properties when fleshing the stubs out.

## Services — the lazy-initialisation trap

`Services/qmldir` declares each singleton the same way `Theme/qmldir` does. A qmldir singleton needs **both** the `Singleton` root type and a `pragma Singleton` line — either alone fails to load, and because a broken sibling takes the whole module down, one bad file surfaces as "Type Audio unavailable" for everything.

- **Quickshell initialises its services lazily.** `Mpris.players`, `UPower.devices`, `Hyprland.workspaces` and `Pipewire` all read as empty until something *observes* them. A `Connections { target: X; function onValuesChanged() {...} }` is what forces population — without one the model stays empty forever and the UI silently shows nothing. Every service wrapper in `Services/` carries one for this reason; it is load-bearing, not decorative.
- **Singletons instantiate lazily on first property access.** Referencing `Audio.volume` from inside a timer callback creates the instance at that moment, so its `Component.onCompleted` polling never gets a chance to run. Reference them from a binding that exists at load time (as `Bar.qml`'s text bindings do), not from a deferred callback.
- **`NotificationServer` is NOT a qml singleton in 0.3.2, whatever the docs suggest.** The shipped qmltypes carries no `isSingleton` flag, so bare `NotificationServer.trackedNotifications` reads `undefined` — silently, with no type error — and nothing ever claims `org.freedesktop.Notifications`. It must be instantiated as an object (`NotificationServer { id: notificationServer }`); that instantiation is what registers the dbus service. Verified by probe: bare access → `undefined`, object → name registered. Set `keepOnReload: true` on it to keep the stack across hot reloads, and advertise capabilities (`bodySupported`, `actionsSupported`, `imageSupported`, …) or apps degrade to plain text. **Swaync is retired** — it held `org.freedesktop.Notifications` until the module above could take the name. The retirement had three parts: the hypr autostart line is gone; the process was killed, and quickshell's server claimed the name on its retry the instant swaync died; and `systemctl --user mask swaync.service` (no root needed) closed the resurrection path — the unit is `Type=dbus` with `BusName=org.freedesktop.Notifications`, so without the mask any restart gap (`pkill -x qs; sleep 1; qs`) could let dbus activation start swaync and steal the name back. The package itself still needs `sudo pacman -Rns swaync` (also takes `gtk4-layer-shell` and `granite7`); until then the two `/usr/share/dbus-1/services/org.erikreider.swaync*.service` files remain on disk, though nothing requests those names.
- **A `NotificationServer` silently discards every notification unless a handler marks it tracked.** `Notify()` emits the `notification` signal and then checks `isTracked()` — an untracked notification is deleted on the spot and never enters `trackedNotifications`. The server owns the dbus name, `notify-send` exits 0, and the stack stays empty with zero errors anywhere: the only fix is `onNotification: (notification) => notification.tracked = true` on the server object. (Source: `NotificationServer::Notify` in 0.3.2 — `if (!notification->isTracked()) { …delete… }`.) This is why SUPER+N "didn't work" for a full debugging round: the bind, the command and the dbus path were all fine.
- **`expireTimeout` is three-valued, and Discord sends -1.** Per the freedesktop spec the final Notify argument is `> 0` = app timeout in ms, `0` = keep until dismissed, `< 0` = server default. Discord (Electron) sends `-1` — captured on the wire with `busctl --user monitor` (app_name "discord", summary "⁨Bathbot⁩ (⁨#general⁩…)", expire_timeout INT32 -1, server replied with id 4). `NotificationCard.qml`'s Timer used to guard on `expireTimeout > 0`, which reads -1 as "never expire" — so every Discord popup stuck until clicked or closed by the app, which reads as "the notification won't go unless the app is open". The card now derives `effectiveTimeout` (`> 0 ? t : (t === 0 ? 0 : defaultExpireTimeout)`, default 5000ms) and runs the Timer on that. If a popup ever sticks again, the next suspect is Quickshell normalizing -1 to 0 before it reaches QML.
- **The card prefers `notification.image` over `appIcon` — that is the sender's avatar.** `Notification::updateProperties` (0.3.2 source) fills `image` from the `image-data` / `image_data` / `icon_data` hint (decoded into a pixmap served through an `image://` provider, so the property is a URL string usable directly as an `Image` source) and otherwise from `image-path` (used as-is when it starts with `file:`, otherwise run through the icon-theme provider — a bare absolute path therefore does *not* resolve). Discord sends the profile picture as `image-data`, which is what swaync showed; the card now renders it in the 22px header slot and only falls back to `Quickshell.iconPath(appIcon)` when the app sent no image at all.
- **A `ListView` whose height binds to its own `contentHeight` never renders anything.** It starts at zero, a zero-height view instantiates no delegates, and with no delegates the content can never grow — the model populates, the signal fires, the screen stays empty. Give the view a height independent of its content (the window's band) and let the *wrapper* track `contentHeight`, which is what the input mask should follow anyway.
- **A delegate's `width: ListView.width` is silently 0 unless the view has an `id`.** `ListView` in a delegate resolves to the *type* object (`typeof` is `"object"`, no error, no warning), whose `.width` is `undefined` — so the delegate's width becomes 0 and anything anchored inside it collapses. This is how the volume card's app rows shipped with no slider: the row's slider anchors `left: nameText.right` (132) against `right: pctText.left` (−82 once the row is 0 wide), a negative span that renders nothing, leaving just the app name. Always `id:` the view and reference `theId.width`.
- **A `Column` gives its children height, never width — a child `Item` with no width is 0 wide, and everything inside it vanishes.** A Column positions children vertically and leaves the horizontal size alone, so a plain `Item { height: 108 }` inside one is 0×108: a `ListView` anchored `fill: parent` in it renders 0×108 (no delegates, no error, no warning) and an overlay `Text` anchored to the same slot is invisible too. This is how the capture page's clipboard list shipped showing nothing at all — not even its "No history yet" empty state. Anchors are illegal directly inside a Column (the standing trap), so the fix is a binding: `Item { width: parent.width; height: 108 }`. A `Text` child survives because it sizes itself to its content; only an `Item` (or a `Rectangle` with no implicit width) hits this.
- **A `Row` top-aligns its children, so two Texts in different fonts never share a line by themselves.** The icon font's line box runs ~19 at 14px against the UI font's ~16 at 13px, both starting at the row's top — the glyph's ink lands ~1.6px below the text's, which reads as the icon hanging low. The fix is one shared line box: `height: glyph.height` on the text plus `verticalAlignment: Text.AlignVCenter`, which centres both boxes and leaves the ink centres 0.3px apart. The number to compare between any two fonts is each glyph's **ink centre in em over its baseline**, measured off the font files with fontTools (`BoundsPen` per glyph, `(yMin+yMax)/2/upm`): the ban glyph's is 0.360em, "OBS offline"'s 0.381em — nearly the same, so matching the line boxes is the whole job. JetBrainsMonoNL's hhea line is 1.32em (ascent 1020, descent −300), which is what Qt lays out — confirmed by the 19px item height at 14px; `TextMetrics` here exposes only `boundingRect` (the layout rect), not the ink, so the font file is the ground truth.
- **`modelData` is context-resolved and nulls the instant an item leaves the model.** A delegate outlives its model item by the exit animation, so any binding to `modelData` reads null on the fading card and floods the log with TypeErrors. Capture once instead — `property var notification: null; Component.onCompleted: notification = modelData` — and pair it with a `RetainableLock { object: …; locked: true }` so the underlying object (Notification is `Retainable`) survives until the card is destroyed. Without the lock the captured pointer dies with the model removal; without the capture the lock is useless.
- **`Quickshell.iconPath("")` mangles into a broken request.** An empty icon name produces `"?fallback=…"` as the image source and logs a load failure per size — guard the call (`appIcon.length > 0 ? iconPath(…) : ""`) when the sender may omit an icon, as `notify-send` does. Named-but-missing icons (`preferences-system-network`, `hwloc` in the launcher) warn the same way and are harmless.
- **`Pipewire` is unusable for sink volume here.** The default sink node stays `ready: false`, so `sink.audio.volume` reads 0 while `wpctl get-volume` reports the truth. `Services/Audio.qml` polls `wpctl` instead — read via `get-volume`, write via `set-volume`/`set-mute`, and re-read in `onExited` so the UI never shows a stale value.
- **Per-app volume goes through `pactl`, not the Pipewire service** (same reason as above). `Services/AppAudio.qml` polls `pactl list sink-inputs` every 2s — each stream's id, `application.name`, first-channel percentage and mute state — and writes via `set-sink-input-volume` / `set-sink-input-mute`. Two traps found while building it: writes must go through a **one-deep queue drained by the process's own exit**, because `running = true` on an already-running Process is a silent no-op and a slider drag would drop every write but the first; and the volume rows keep a **local visual value while dragging**, because the 2s poll read-back landing mid-drag snaps the handle back to the old value. Commits throttle to one per 100ms so the audio follows the drag live without a pactl per mouse-move.
- **`Networking` returns nothing here** — zero devices and `wifiEnabled: false` while NetworkManager is active and connected. `Services/Network.qml` polls `nmcli` instead: `device status` decides connectivity and medium, then `device wifi` adds signal strength.
- **No service covers memory.** `Services/Memory.qml` parses `/proc/meminfo`, using `MemAvailable` rather than `MemFree` as the basis for "used".
- **No service covers brightness either — `Services/Brightness.qml` polls `brightnessctl`.** The `/sys/class/backlight/*` nodes are root-owned, and `brightnessctl` (installed, works without sudo) already knows how to find the device and write it back. `brightnessctl -m` returns one line per device — `nvidia_0,backlight,81,81%,100` — so the device name comes off the read and is passed back as `-d <name>` on every write, which keeps read and write on the same device on a machine with several backlights. Unlike every other service here this one does **not** poll at boot: the theme page is its only consumer and it is usually closed, so the 2s timer runs only while `Brightness.active` is true. ThemeCard flips `active` from its own `onVisibleChanged` and calls `refresh()` on the way in, so the slider is live the moment the page opens and the shell forks nothing the rest of the time. Verified by probe: idle for 2.5s leaves `available` false, activating reads the real value, `setBrightness` and `nudge` both read back correctly.
- **No service covers wallpapers either — `Services/Wallpapers.qml` lists `~/.config/rofi/wallpapers` and applies a pick.** That directory is the one the rofi wallpaper menu (SUPER+G) reads from; it is runtime data and is not part of this repo, so it is listed at runtime rather than referenced as a checked-in path. A pick is applied exactly the way the rofi menu's script does it — `awww img <path> --transition-type grow --transition-duration 2.5 --transition-fps 60`, then `matugen image <path> --prefer saturation` — with the two steps chained as separate argv rather than run through a shell, so the paths need no quoting (these filenames carry spaces and non-Latin characters). A click landing while a previous pick is still transitioning would be dropped by a bare `running = true` (a silent no-op on an already-running Process), so the newest pick waits in a one-deep `pending` queue drained by matugen's exit. `current` is parsed out of `awww query` (`currently displaying: image: <path>`, taken to end-of-line so it survives spaces) and is moved **on the click**, not when the transition ends — awww takes 2.5s, and a selection that only highlights once the wallpaper is already up reads as a dropped click. There is no polling: the listing is a one-shot `find` and the current wallpaper a one-shot query, both driven by ThemeCard's `onVisibleChanged` alongside the brightness refresh. **Qt has no WebP plugin on this box** (`qt6-webp` is not installed; `/usr/lib/qt6/plugins/imageformats` carries only gif/ico/jpeg/pdf/svg), so the two `.webp` files in the directory decode to `Image.Error` and show as bare `cardHighlight` plates — the click still applies them. `sudo pacman -S qt6-webp` fixes it; flagged to LO, not installed.
- **No service covers audio visualisation either — `Services/Cava.qml` runs a second, headless cava.** The terminal cava (`cava/.config/cava/config`) draws in a terminal; this one runs in `raw` mode and streams bar heights to stdout, which the shell parses into the media card's background bars. cava takes only `-p <config>` on the command line — no flag for any of it — so the raw config is a separate file, `quickshell/.config/quickshell/cava-raw.conf`, deployed by stow. Verified format: `"v0;v1;...;vN\n"`, semicolon-separated, newline-framed, **0–1000 on a fixed scale** (`bit_format` is ignored in ascii mode — 8bit and 16bit both cap at 1000), 32 bars mono. **cava is always-on: the process starts with the shell and never stops.** That is a measured trade, not an oversight — cava's cold start is ~375ms (16ms exec + config parse, then ~360ms from opening the audio input to its first frame; confirmed on the real pipewire path, not just a fifo), it is not a buffer fill (pre-dumping 2s of audio does not shorten it) and not framerate-dependent (30/60/240fps all ~400ms), while its steady-state latency is only 21ms, so the bars track the music tightly. Gating on the media page therefore paid 375ms on every open — hidden by the 300ms pop on a hover-open, fully exposed on a tab switch. Warm cost: 1.3% of one core and ~88MB RSS, less than the pollers the shell already runs forever (AppAudio forks `pactl` every 2s for the session's life). `running = false` does terminate the child (verified — the stream stops dead, no orphan), so the gate could come back if it ever needs to; the levels are no longer zeroed on close, since there is no close.
- `UPower.displayDevice` can report `ready: false` with a zero percentage until the device list is enumerated, so `Battery.qml` prefers the real `isLaptopBattery` device from `UPower.devices` and only falls back to `displayDevice`.
- Reading a `Process`'s output: attach a `StdioCollector` to `stdout` and handle `onStreamFinished`, where `this.text` holds the whole output. `waitForEnd` is not needed for short-lived commands. **For a continuous stream, use `SplitParser` instead — see the API section.** `StdioCollector` is the wrong tool there: it accumulates every byte it has ever seen (measured 792 → 7022 bytes over 8s at 100 lines/s, which at cava's 60fps would be ~830MB/day), and its `text` does not update until the stream ends unless `waitForEnd` is false.

## Working agreement

- **Never drive the user's input.** No synthetic keyboard/mouse via `/dev/uinput`, no screenshots to verify interactive behaviour. Inputs and clicks are the user's to test.
- **Verification is a separate phase.** When something needs checking, do it in a clearly separated troubleshooting step — not interleaved with implementation edits. Inline load checks (`qs -p ~/.config/quickshell` starts clean) are fine.
- **Parallelize with subagents when the work splits.** Independent workstreams — a layout pass on one page while a doc edit lands, two modules that don't touch each other — go to subagents in parallel instead of queueing behind each other. Brief each one with the full context (AGENTS.md first, the verified traps, the verification protocol, and the do-not-commit rule), then verify its work before it lands; sequential work where each step needs the last one's result stays in the main session.
- **All config lives here.** Hyprland, matugen, rofi — everything is a package in this repo now. The old `~/hypr-dotfiles` repo is a read-only archive until burn-in passes; never edit it.

## Quickshell API — verified against 0.3.2, not the 1.x scaffold

The Arch `*.qmltypes` files are **stale** (the Hyprland one is an empty stub). Trust runtime probes, not typeinfo. Verified facts:

- `Process.command` takes a **QStringList**, not a string. A plain string becomes a single argv element and fails to start. `Services/Matugen.qml`'s list form is correct.
- `DesktopEntry.command` is a **QStringList** (stringifies comma-joined). Pass it straight to `Process.command`; field codes like `%U` are already stripped.
- `DesktopEntries.applications` is an `UntypedObjectModel`. Read it as **`.values`** (a JS array), and wait for the **`applicationsChanged`** signal — it is empty at `Component.onCompleted` time. Same pattern for `Hyprland.workspaces.values`.
- **Services initialise lazily and stay empty until observed.** See the Services section — this is the single most common cause of a silently blank widget.
- **`PersistentProperties` does NOT survive a reboot in 0.3.2 — use `FileView` for anything that must.** The docs sell it as holding properties "across a reload", and that is all it does: probed with a throwaway config, a property set at runtime and the process killed (both SIGTERM and `qs kill`) never produced a state file at all — no `~/.local/state/quickshell` entry appears, and a fresh process comes back with the declared default. The `reloadableId` path only carries state between the old and new *engine generations* of a hot reload, in memory. The theme mode (`Theme.themeMode`) is therefore persisted with a `FileView` at `~/.local/state/quickshell/theme-mode`: `blockLoading: true` plus a `text()` read in the singleton's `Component.onCompleted` (a binding on `text()` also works but re-evaluates when the load settles, and QML bindings notify unconditionally, so it fires a spurious change signal and rewrites the file on every boot), and `setText()` from `onThemeModeChanged` guarded by a `text() !== themeMode` check so a no-op boot never touches the file. A first boot with no file creates one: `onLoadFailed` writes the current mode, so the state is explicit from then on rather than only appearing once the switch is first used. `printErrors: false` keeps the normal first-boot "file missing" load failure out of the log. State files go in `~/.local/state`, never `~/.config/quickshell` — that path is this repo through stow, so a file written there lands in git as an untracked artifact.
- `Hyprland.workspaces` carries the special workspace (`id === -98`) and is unordered. Filter to `id > 0` and sort before rendering.
- **`Hyprland.dispatch(request)` interpolates the request raw into a Lua call** (`return hl.dispatch(<request>)`), and this machine's Hyprland runs a Lua config. The legacy string form `"workspace N"` dies with a Lua syntax error (`')' expected near '1'`), and the quoted form `"'workspace N'"` dies with `expected a dispatcher`. The working request is a real dispatcher object: **`Hyprland.dispatch("hl.dsp.focus({workspace = " + id + "})")`** — confirmed switching *and* creating missing workspaces. `hyprctl dispatch workspace N` from the shell hits the same Lua wrapper and fails identically, so a `Process` fallback is not a way out. Native `workspace.activate()` also works, but only for workspaces that already exist (useless for the bar's persistent 1–4 placeholders). Dispatcher syntax ground truth is `hypr/.config/hypr/keybinds.lua` in this repo (workspace switching is `hl.dsp.focus({ workspace = i })`; `hl.dsp.workspace` is a table, not callable). Note: `Hyprland.workspaces`' `valuesChanged` does **not** fire when only the active flag changes — verify switches with `hyprctl activeworkspace`, not with the model signal.
- `Mpris` player fields are `trackTitle` / `trackArtist` / `trackArtUrl` — there are no plain `title` / `artist` properties, and they read `undefined` until a track is loaded. **Listen to `postTrackChanged`, never `trackChanged`:** `MprisPlayer::onMetadataChanged` emits `trackChanged` *before* assigning `bMetadata` (the metadata-derived fields are bindings on it, updated inside a property update group after the signal), so a `trackChanged` handler reads the *previous* track — the bar sat one track behind on every skip until `Services/Media.qml` was switched. `postTrackChanged` fires after the group closes with every derived property fresh. `isPlayingChanged` and the `canGo*` signals are ordinary property notifies and are safe as-is. (Source: `src/services/mpris/player.cpp`, `onMetadataChanged`.)
- `Quickshell.screens` is a JS-array-like list; use `.length` / `[i]`, not `.count`.
- `Quickshell.env()` is a **method**, not a property.
- `Timer` and `Component` need an explicit `import QtQml` — `import Quickshell` alone does not provide them.
- **`Easing` is grouped-property-only, and Qt 6 renamed the bezier knobs.** `Easing { }` as a standalone object fails with "Element is not creatable" — it only exists as the `easing` group on an animation. And the bezier control points are **not** `controlPoint1`/`controlPoint2` (both fail with "Cannot assign to non-existent property"); Qt 6.12 exposes a single flat list, `easing.bezierCurve`, in `[c1x, c1y, c2x, c2y, endX, endY]` order — six numbers per cubic segment. A control-point y above 1 is what produces the overshoot: with `[0.34, 1.25, 0.64, 1.0, 1.0, 1.0]` the curve peaks at 1.0204 (measured), where `Easing.OutBack` peaks at 1.1000. Sweep of the first control point's y with the rest fixed: 1.12→0.4%, 1.15→0.6%, 1.20→1.3%, 1.25→2.0%, 1.30→3.0%, 1.35→4.1%, 1.50→8.0%, 1.70→14.3%. The cards shipped on 1.35 (4.1%) first and were nerfed to 1.25 (2.0%) — "subtle but still there."
- `PanelWindow`: use `implicitHeight`, not `height` (the latter is deprecated and warns). `exclusiveZone` and `ExclusionMode.Ignore` both exist.
- **`WlrLayershell` needs `import Quickshell.Wayland`.** The attached object (`WlrLayershell.layer: WlrLayershell.Overlay`) resolves only with that import — without it the config dies with "Non-existent attached object" at the assignment. Layer enum is `Background / Bottom / Top / Overlay`. Corners and the notification popups both sit at Overlay, so they show above fullscreen windows — that is the point of the trick, and also its cost. **Property syntax only, never an attached-object block:** `WlrLayershell { layer: ... }` loads clean in 0.3.2 but leaves the window at Top *and* spawns a stray default-sized (100×100) Overlay surface that hyprland centers in the workarea — a white square mid-screen owned by nothing in the QML. Bisected with throwaway probe configs (block → stray square, property → one clean surface) before touching the live module; the notifications module shipped with the block and wore the square until it was caught.
- **Nothing rounds the physical screen.** `Modules/Corners` paints four corner cutouts (a `Canvas` path per corner: square minus quarter-disc) in `Theme.screenCornerColor` at the Overlay layer, with `ExclusionMode.Ignore` so the monitor's reserved area is untouched. Fullscreen content loses its corner pixels and the color must match the wallpaper to blend — both inherent to the approach. Off switch is `Theme.screenCornersEnabled`.
- **A full-screen layer surface eats all input unless masked.** A `PanelWindow` covering the whole monitor accepts clicks and scrolls across its entire extent (layer-shell input region defaults to the whole surface) — a transparent click-through overlay is *not* the default. `PanelWindow.mask` (a `Region`, default property `regions`, `intersection: Intersection.Combine` to union children) clips rendering **and** input: only the masked area is clickable, everything else passes through. Region items carry `x/y/width/height` plus per-corner radii (`topLeftRadius` etc.), so a mask can match a rounded cutout exactly. `Modules/Corners` sets one to its four cutouts; without it the desktop goes dead the moment the shell loads. If input ever dies after a shell change, `pkill -f 'qs -p'` is the instant recovery.
- **A mask can track an item live.** `Region { item: someItem; radius: someItem.radius }` follows the item's geometry and corner radius through animations — `PendingRegion` connects every geometry property to a `changed()` signal, and `ProxyWindowBase` re-applies the mask on polish. Regions nest: `regions` is the default property, `Intersection.Combine` is the default intersection, and a child's `item` overrides its own x/y/width/height. This is what lets the bar window be *taller than its exclusive zone* (the island card pops open past the reserved band) without the extra area swallowing clicks: `shell.qml` points the bar's mask at a pill region with a nested card region, and both are explicit geometry. The pill's because its canvas is taller than the bar by the roll's depth, and an item-based region would cover that strip and swallow clicks below the bar's edge — so it pins `x/y/width` to `pillItem` with `height: bar.barHeight` and the four corner radii bound to `pillItem.radius`. The card's because the card pops open *scaled* and a Region tracks an item's geometry, never its transform — an `item:`-based region would sit at full width through the whole pop and swallow clicks beside the animating card — so it binds `x` to the popped width centered under the pill, `y` to `cardItem.y`, and `width`/`height` to `cardWidth * pop` / `(cardHeight + cardRadius) * pop`, making the region the visible card at every frame and nothing at all when collapsed. If the child region ever fails to register, the failure mode is safe — only the card's clicks die, the bar keeps working. Coordinates are logical, not device pixels.
- **A `MouseArea` only accepts hover events when `hoverEnabled` is true.** A non-hover MouseArea stacked above a hover one does not steal `containsMouse` — that is what lets the island's hover trigger sit *under* the media card's buttons and stay hovered while the cursor is on them. The inverse bites too: a hover-enabled area above `cardZone` *does* steal the hover from it, which is why the tab buttons (hover-enabled for page switching) are OR'd into `hovered` through `columnHovered` (`columnZone.containsMouse || mediaTab.containsMouse || volumeTab.containsMouse || sessionTab.containsMouse`) — without that, resting the cursor on a tab button reads as "left the card," the grace timer collapses the island, and it reopens under the cursor in a loop. (`QQuickMouseArea::setHoverEnabled` calls `setAcceptHoverEvents(h && enabled)`.)
- **The pill is a `Canvas`, not a `Rectangle`** — the island's junction needs the bar's bottom edge to roll where the card emerges, and a Rectangle's outline is fixed. The card's side edges meet the bar's bottom edge at a hard 270° corner; the roll replaces it with a tangent fillet per side — one arc, tangent to the bottom edge (horizontal) where it leaves it and tangent to the card's side edge (vertical) where it lands, centered in the empty region outside the corner. It is material-growing, not a bite: no gap opens, and the card's tucked corners stay hidden behind the roll — which is why the smoothing lives on the pill and not on the card. The canvas is `barHeight + cardRadius` tall because the rolls hang below the bottom edge and a Canvas clips its painting to its own bounds; the extra strip is transparent except for the rolls, and shell.qml's mask pins the pill's input region to the bar's own 40px band so the strip never swallows clicks. Traversal (bottom edge R→L, `bh = root.barHeight` — not the canvas height): right roll is `lineTo(cx+fr, bh)` → `arc(cx+fr, bh+fr, fr, -π/2, -π, true)` → `lineTo(cx, bh)`; left roll is `lineTo(nx, bh)` → `lineTo(nx, bh+fr)` → `arc(nx-fr, bh+fr, fr, 0, -π/2, true)`. The corner where each detour rejoins the bottom edge is interior — the card's material fills it — so only the arc and the card's edge form the visible boundary. The roll's radius is neither a constant nor tied to `expanded`: it tracks the card's visible overhang minus whatever the card's own bottom corner is rounding off — `over = cardClip.height - cardRadius; rb = min(cardRadius, max(0, over/2)); fr = clamp(over - rb * pop, 0, cardRadius)` (the `rb * pop` because the card's painted corner radius is rb scaled by the pop) — so the roll's tip lands exactly where the card's corner arc begins at every height, both curves tangent-vertical there, and the junction reads as one smooth S with no gap and no detached tab through the whole pop in both directions. The rolls also sit at the card's *popped* width: `nx`/`cx` come from `cardWidth * pop`, not the resting width. Tying the roll to the boolean instead pops the rolls off the instant a collapse starts, leaving the sharp corner bare for the full 240ms the card takes to retreat. The card is a `Canvas` for the same class of reason: its bottom corners must stay rounded through the pop, and a Rectangle's radius is fixed — a 24px corner on a card the clip has not finished revealing reads as a clipped square, so the rounding only appears once the card is fully open. The card's canvas fills the clip's height and is centered in it at the resting `cardWidth` (the clip runs `popOvershoot` wider to leave the overshoot room), with a `Scale` transform (origin top-center, `xScale: pop`) doing the horizontal pop; it repaints every frame via a `Connections` on `cardClip.heightChanged`, paints the rounded rect with the top corners at `cardRadius` — hidden behind the bar — and the bottom corners at `rb = min(cardRadius, max(0, (height - cardRadius)/2))`: full radius once the visible band can hold one, a semicircular cap while it is shorter, zero before the card clears the bar's bottom edge. The card body is `Theme.cardBackground`, the island surface shared with the workspace pill (`#e2e2e6` under the white light pill, `#1c1c20` under the dark pill) — the card's content palette flips with it: light-on-dark in the dark palette (`cardForeground` `#e8e8ea`, `cardDim` `#9a9aa0`, `cardHighlight` `#3a3a40`, `cardInk` `#e8e8ea`), dark-on-light in the light one (`#1b1b1f` / `#6e6e73` / `#d2d2d6` / `#1b1b1f`), with `cardOnInk: cardBackground` for the knockout transport glyphs. After the fill it paints the menu column strip down the left edge back in `barBackground`: the outline path is still current after `ctx.fill()`, so `ctx.save()` → `ctx.clip()` → `fillRect(0, 0, columnWidth, h)` → `ctx.restore()` hands the strip the card's own rounded left corners for free (its right edge stays square against the card), and it scales with the pop like everything else on the canvas. The strip's width tracks the column's hover expansion (`columnWidth` = 56 + (150−56) × `columnExpand`), so the repaint `Connections` also watches `columnExpandChanged` — one repaint per frame of the 200ms expansion — on top of `barBackgroundChanged` and `cardBackgroundChanged`, so a matugen regeneration repaints either half. That paint sits *behind* the pages (the content Item renders above the canvas), which is fine for the resting strip — the pages keep an 80px left margin — but the expansion reveals 56..150px of page content through the transparent buttons, so a plain `Rectangle` in `barBackground` (declared after the pages, before the buttons; `x: cardColumnWidth`, `width: columnWidth - cardColumnWidth`, zero at rest, no hover taken) covers the revealed region above the pages. The content Item stays a child of the canvas and renders above the paint. Three details bite: `Canvas` has no `radius` property, so the pill declares its own `readonly property real radius` for the mask; repaints must be requested explicitly (a `Connections` on `cardClip.heightChanged` drives the per-frame pop repaint, plus a `Connections` on `Theme.barBackgroundChanged` for matugen regenerations); and every `ctx.arc` must start at the point the path is already standing on, or canvas silently inserts a straight connector and the curve collapses (Corners.qml learned this the hard way).
- **`getImageData` reads the DPR-scaled backing store, not logical pixels.** On this monitor (scale 1.6) a sample at logical (400,34) actually reads logical (250,21) — verified by sampling the pill's rounded caps (opaque inside the curve, transparent outside). When probing Canvas output, multiply logical coordinates by the device pixel ratio first. This is how the roll shape was verified without a screenshot: alpha runs along rows below the bottom edge reconstruct each fillet (`.0-293 O294-299 .300-899 O900-906 .909-1199` at y40 when fully expanded — two tapering bumps at the card's edges, nothing between them; the body rows unchanged; all transparent when collapsed). Driving `cardClip.height` to exact mid-pop values verifies the tracking: at height 30 (fr=6, rb=6) the roll's body shows at y38 (`.0-298 O299-299 .300-899 O900-901`) while the tip rows y40/y42 fall below the alpha threshold — a 6px fillet is a hairline there — and the card's own corner arc starts at card-local 24 (full width, `O0-599`) and curves by local 26 (`.0-0 O1-599`, left boundary 0.34, right 599.66); at height 40 (fr=11, rb=11) the roll shows at y42 (`O900-901`), tips at y44 (`O900-900`) and vanishes by y47, with the card full width at local 29 and curving at local 31. The roll's tip row always equals the card's arc-start row (42 at height 30, 47 at height 40) — that equality is the junction check. Fully expanded, the card's bottom corner is the exact r24 quarter circle (all probed values in this paragraph were taken at the original 18px radius): `.0-0 O1-599` at card-local 455 and `.0-6 O7-593` at 464. Five probe gotchas: `Canvas.canvasSize` reports the *logical* size (1200×54) while the store is device-scaled (1920×86.4), so derive the scale from the monitor, not from `canvasSize`; `getImageData` does not clamp out-of-bounds requests — it returns the requested size filled with transparent, so a clamp-probe of the store size silently lies; `Screen.devicePixelRatio` reports 2 on this monitor while the real output scale is 1.6 — trust the cap-edge arithmetic, not the property; `getImageData` sees only the canvas's own paint — child items (the card's art/text/transport, the pill's topBand) render above the canvas texture in the scene graph and never appear in the store, so probing a child's pixel reads the canvas underneath (this is why the play button probed white); and driving `cardClip.height` from JS fights the `pop`-derived binding — the assignment sticks until the next animation frame re-asserts it, so pin it with `cardClip.height = Qt.binding(function () { return N })` (or stop the pop animations and set `pop` directly) when a probe needs a value to hold.
- **The bar hides itself over fullscreen windows — that is Hyprland, not a bug.** `CLayerSurface::onCommit()` (src/desktop/view/LayerSurface.cpp, Hyprland 0.56.2) sets the alpha *goal* to 0 for every layer below Overlay while the monitor has a fullscreen window; Overlay layers keep goal 1. `hyprctl -j layers`' per-layer `alpha` field is that goal, so a fullscreen game/video reads bar 0 + corners 1 — expected, and nothing is wrong with the QML. Check `hyprctl -j clients` for a `fullscreen` client before investigating an invisible bar. (This repo went down a long rabbit hole blaming hot reloads and launch paths for alpha 0 — all of it was osu! running fullscreen.)
- **A fullscreen game can kill EGL for new clients outright — one level worse than alpha 0.** With a 3D game saturating the GPU (Endfield.exe under wine at 222% CPU; osu! before it), a fresh quickshell fails with `eglError: 0x3003` (EGL_BAD_ALLOC), `Failed to create QRhi on the render thread; scenegraph is not functional`, and one `Failed to create graphics context` error per layershell window. The QML itself loads fine — "Configuration Loaded" prints before the errors — so this is not a config error, and no amount of config restarting helps. Two traps: a hot reload that dies this way leaves the old instance alive with a dead render thread, and that instance renames its comm from `qs` to `quickshell`, so `pkill -x qs` silently stops matching it (kill `quickshell` too, or spot it in `ps -eo pid,pcpu,comm` as a ~12% CPU qs that should be dead). Recovery without touching the game: `QT_QUICK_BACKEND=software setsid qs` renders the shell through wl_shm with no EGL context at all — fully functional at ~20% CPU; restart plainly once the game exits.
- **That goal is only re-evaluated when the layer surface itself commits** (a `wl_surface.commit` from quickshell: clock tick, hover, media change, workspace switch). `arrangeLayersForMonitor` does not touch alpha, so after fullscreen exits the bar can stay invisible until its next commit — up to ~60s with the minute-precision clock, or instantly on any interaction. If the recovery lag ever matters, the fix is a client-side keep-alive commit (something visible changing every second), not a config change.
- **Children of a `PanelWindow` do not auto-fill its content item.** A plain `Item` declared inside one stays 0x0 unless it sets `anchors.fill: parent` (or explicit width/height). Anchors that reference `parent` then resolve against a zero-size parent — `horizontalCenter` parks the child at negative x, half off-screen. `Launcher.qml` sidesteps this by making the `PanelWindow` itself the component root; `Bar.qml` uses `anchors.fill: parent`. Verify any new module's root geometry at runtime before trusting it.
- **A child's `visible` reads effective visibility, not its declared value.** An item inside a hidden page reads `false` no matter what its own binding says, while its geometry still polishes at startup — so a geo timer can measure an invisible page's layout, but a `visible` flag is meaningless unless the page is the active one. Verified on the capture page: the record row's dim "OBS offline" Text read `false` under the hidden page and `true` the instant the page was forced visible, with the pill's own binding reading `false` throughout. To probe a page's visibility, temporarily flip its instance's `visible` in Bar.qml — the `page(name)` IPC route does not work (an IpcHandler function taking a parameter reports "Function not found"; the parameterless `session` route answers fine). **Forcing `visible: true` at load also means `onVisibleChanged` never fires** — the property never *changes* — so anything riding it never runs. This cost a probe round on the clipboard list: the page was force-visible from load, `count` read 0, and the first suspect was a broken `required property int index`; the real cause was the refresh itself (`onVisibleChanged: if (visible) clipListProcess.running = true`) never firing. The probe has to kick the process itself, exactly as the page open would. In production the page opens false→true, so the bug is probe-only — but the empty list it produces looks exactly like a delegate failure.
- `SystemClock.Seconds` and `Variants` both exist as the scaffold uses them.
- **Tray menus need `//@ pragma UseQApplication`.** `SystemTrayItem.display()` renders through Qt's platform-menu layer, which only exists when quickshell runs as QApplication — without the pragma (first line of `shell.qml`) every right-click logs `Cannot display PlatformMenuEntry as quickshell was not started in QApplication mode` and no menu appears. The pragma is read at startup only: a hot reload does not apply it, a full restart does.
- **There is no reload path except a restart.** `qs` has no reload subcommand (`log`/`list`/`kill`/`ipc`/`msg` only), and the file watcher ignores mtime-only changes — `touch shell.qml` does nothing, only content edits reload. SUPER+R therefore runs `pkill -x qs; sleep 1; qs` (`hypr/.config/hypr/keybinds.lua`); the relaunch inherits `WAYLAND_DISPLAY`/`XDG_RUNTIME_DIR` from hyprland's exec environment, the same path the autostart uses, and the sleep keeps the dying instance from briefly double-drawing the bar.
- **Reading a *continuous* stream needs `SplitParser`, not `StdioCollector`.** This is the one that cost the most to find. `StdioCollector` accumulates every byte it has ever seen — measured 792 → 7022 bytes over 8s at 100 lines/s, which at cava's 60fps would be ~830MB/day — and its `text` does not update until the stream ends at all unless `waitForEnd: false`. `SplitParser` is the type built for this: set it as `Process.stdout` with a `splitMarker`, and it emits the inherited `DataStreamParser.read(QString)` signal **once per chunk, with the marker already stripped**, while consuming the buffer. Verified: 711 chunks over 8s with `text` pinned at 9 bytes throughout. Handler syntax is `onRead: (data) => { … }`. Two gotchas: the signal is named `read` and is a **signal, not a method** — calling `collector.read()` fails with "Insufficient arguments" and silently kills the handler; and `SplitParser` needs both `import Quickshell.Io` and the marker set before the process starts. `Services/Cava.qml` is the working example. Setting `Process.running = false` does terminate the child (verified — the stream stops dead, no orphan), so an `active` gate is enough to keep a streaming process from running forever.

## QML import rules that bite here

- From `Modules/<Name>/<Name>.qml`, the Theme import is **`import "../../Theme"`** — two levels up. `../Theme` silently resolves to the nonexistent `Modules/Theme`.
- Every module directory needs its own `import "Modules/<Name>"` line in `shell.qml`; QML does not propagate imports.
- A directory containing a `qmldir` does **not** implicitly expose its sibling files as types. `Theme/qmldir` must declare `Colors 1.0 Colors.qml` or `Theme.qml`'s `Colors {}` reference fails with "Colors is not a type".
- `Launcher` must be instantiated once in `ShellRoot`, **not** inside the per-monitor `Variants` delegate (a `Component` accepts only one root object).

- **The launcher card pops up from the screen's bottom edge — the island card's pop, mirrored.** One `pop` value (0→1) drives the clip's height (`pop × (cardHeight + cardRadius)`, anchored to the window's bottom with a `-cardRadius` bottomMargin) and the card canvas's horizontal `Scale` (origin center, `xScale: pop`), so the card grows upward out of the screen's bottom edge. `popIn` 300ms `Easing.Bezier` — a tamed back-ease, `bezierCurve: [0.34, 1.25, 0.64, 1.0, 1.0, 1.0]`, which lifts the curve to ~1.02x before it settles (measured peak 1.0204) instead of OutBack's 1.1x spring; the clip still runs `popOvershoot` 1.12 wide so the overshoot isn't shaved square. `popOut` 200ms OutCubic (no undershoot). Neither animation sets `from`, so each picks up from the current value and a toggle mid-pop interrupts cleanly (`onOpenChanged` stops the other before starting its own). **The window is mapped for the shell's whole life — never toggle `visible`.** Remapping the full-screen layer surface on every open costs the first ~56ms of the pop-in (9 dropped frames at 165Hz, measured: 36ms + 20ms gaps right after `open=true`, then a clean 6ms/frame cadence), which reads as the card hitching into motion; the pop-out never paid it because the window was still mapped while retracting. With `visible: true` the measured deltas are 1/3/5/6/7ms from the first tick — zero stalls. The bar's window is always mapped for the same reason. An always-mapped full-screen surface would eat every desktop click, so the input mask carries the open/closed state: `Region` at full extent while `open || pop > 0.001` (the click-outside MouseArea needs the whole surface), zero-sized once the card has retracted (click-through — the same collapse-to-nothing the bar's island card region does when the island is closed). `reset()` (the filter clear) runs from `popOut.onStopped` guarded on `!open` — clearing in `close()` would visibly empty the card on its way down. The card is a Canvas because its TOP corners are the reveal edge and must track the visible height (`rt = min(cardRadius, max(0, (h - cardRadius)/2))` — the island's bottom-corner formula, mirrored); the bottom corners keep the full radius and are never visible — **the clip tucks a corner radius below the screen's bottom edge**, the exact mirror of the island's card tucking up behind the bar by its corner radius (its clip's `topMargin` is `barHeight - cardRadius`). The screen's bottom edge plays the bar's role: the card sticks out of the edge with its rounded bottom corners hidden behind it, instead of sitting on the edge with them notched into view. Below the screen edge the path may invert while the band is shorter than the radius (arc centers under the canvas), but the window clips all of it — probe-verified at pop 0.075/0.5/1.0: square cut at the screen edge, tracking top corners, no diagonal shard. `cardHeight` binds to the content column's height + 20 (10px visible padding top and bottom); the ListView's height is **fixed at 7 × 40** so the card never resizes when the filter narrows the results — a shrinking card moves the pop's target under the animation and reads as jitter. The column anchors to the canvas's bottom with a `cardRadius + 10` margin: the canvas's bottom sits a corner radius below the screen edge (tucked), so the margin clears the tucked strip and leaves the content 10px above the screen's bottom edge — the mirror of the island content's topMargin (cardRadius + 4 below the bar's edge). **The card's side edges meet the screen's bottom edge at a hard 90° once open — the island's pill smooths the same junction (bar bottom edge vs card side edges) with tangent fillet rolls, and the launcher mirrors those as corner tabs.** A second `Canvas` inside the clip (declared before the card canvas, so it paints under it; unscaled, `anchors.bottomMargin: cardRadius` to cancel the clip's tuck so the canvas's bottom is exactly the screen's bottom edge, H in the paint; width `cardWidth * popOvershoot`, height `cardRadius`) flares OUT from each card edge down to the screen's bottom edge — material-growing, not a bite. The tab's tip lands where the card's own reveal-edge corner arc begins at every height: `over = cardClip.height - cardRadius`, `rt = min(cardRadius, max(0, over/2))` (the card's painted corner radius), `fr = max(0, min(cardRadius, over - rt))` — no pop factor on `rt`, because the card scales horizontally only (`xScale: pop`), so the painted corner radius is vertically unscaled. Right tab: `moveTo(cx, H)` → `lineTo(cx+fr, H)` → `arc(cx+fr, H-fr, fr, π/2, π, false)` → `lineTo(cx, H)`; left mirrored (`arc(nx-fr, H-fr, fr, π/2, 0, true)`), with `cw = cardWidth * pop`, `nx = (w-cw)/2`, `cx = nx+cw`. Repaints via `Connections` on `cardClip.heightChanged` (per-frame pop tracking) and `Theme.cardBackgroundChanged` (matugen regeneration); a `MouseArea { anchors.fill: parent }` on the canvas swallows clicks on the flares so they read as card, not dismiss layer. Probe gotcha: a canvas's FIRST paint runs at DPR 2.0 and repaints at the real 1.6 once the window settles, so calibrate the store scale from a paint on the same canvas, not a sibling.

## Icons

- **Status icons are Nerd Font glyphs, not images.** `Theme.iconFont` is `"JetBrainsMonoNL Nerd Font"` (verified to cover Font Awesome `f000–f381` and Material `f0001–f1af0`). It is set explicitly on each glyph `Text` — the bar's UI font is not an NF family, so inheriting it renders every glyph as tofu. The bar's status readouts (network, volume, battery) are icon-only: state rides the glyph tier (ban/wifi/globe, speaker-off/down/up, bolt/tiered cells) plus the palette color, with no value text — the SSID and percentages were deliberately dropped. Because the glyph is text it inherits `color` and follows the palette/dark toggle for free.
- **Do not use SVG for status icons.** Qt's SVG renderer (`libqsvg.so`, installed) draws symbolic SVGs as authored and does not resolve `currentColor`, so the fill is baked in — one color cannot serve both the light and dark pills. SVG app icons in the launcher are fine precisely because brand color is the point there.
- **Tray icons ride in their brand colors, all inside one pill.** The SNI icons used to be tinted to the bar ink with a `ColorOverlay`; they now render untinted, and the whole set shares one pill cut from the workspace pill's cloth — `Theme.barWorkspacePill` surface, `workspacePillHeight` (30) with `height/2` radius, 4px side padding, hidden entirely when the tray is empty (an empty tray would otherwise leave an 8px sliver). The tint was the file's only Qt5Compat user, so the import is gone. Each icon's MouseArea stays on the icon rather than the pill: `mouse.x/y` feed `modelData.display()` and must keep the icon-relative origin.
- **Custom two-tone marks are drawn in QML, not shipped as assets.** `Modules/Bar/HeaderIcon.qml` is the precedent: a 40×20 white plate with a black diagonal arrow painted by a small `Canvas` — a Nerd Font glyph can't carry two colors and SVG bakes its fill, so neither route can do a two-tone mark. The colors are fixed white/black in both palettes by design (a brand mark, not palette content — it does not invert with `darkMode`, which makes the white plate subtle against the light card), so the Canvas needs no repaint wiring. It sits in the volume page's title row in place of the speaker glyph.
- **Launcher app icons stay `Quickshell.iconPath` + `Image`** (`sourceSize` 30; bump to 48 if they ever look soft at the 1.6 DPR). `Quickshell.Widgets.IconImage` is a thin `Image` wrapper — same loader, icon-sane defaults, no SVG magic. Themeable-vector fallback if ever needed: `Shape` + `PathSVG`.
- **Glyph coverage is per-codepoint, not per-range.** `F538` (md-memory) sits in the gap *between* the FA and Material blocks — not inside either — and renders as tofu (it shipped once as the memory icon before that readout was removed). Verify any new glyph against the font before shipping it: `fc-query -f '%{charset}\n' <font-file>` lists the covered ranges, and a codepoint is only safe inside one of them. MDI codepoints are the exception — the whole `f0001–f1af0` block prints as one range, so `fc-query` cannot confirm an individual MDI glyph; use fontTools (`TTFont(path).getBestCmap()`) for those, as was done for `door-open` (U+F081C). Above U+FFFF a QML `text:` needs the UTF-16 surrogate pair, not `\uXXXX` (which takes exactly 4 digits and would swallow the following character) — compute it with `struct.unpack('<HH', chr(cp).encode('utf-16-le'))`.

Use `--skip-worktree`, **not** `--assume-unchanged`: assume-unchanged is a promise git may re-check and a `checkout`/`reset` can silently overwrite the local file, while skip-worktree makes git leave the working-tree copy alone on every operation including merges. The flag lives in `.git/index`, so it is **local and not shared** — a fresh clone comes up unmarked and dirty. `install.sh` re-applies it on every run (after the stow loop, guarded on `.git` existing and each path being tracked, so a partial checkout does not fail the install), which is the normal path back; the manual equivalent is `git update-index --skip-worktree <the five paths>`. To make a real change to one of them (a template edit that should be committed), unmark first with `--no-skip-worktree`, commit, then re-mark. A side benefit: `git add -A` / `commit -a` can never sweep a stray palette edit into a commit by accident.

# AGENTS.md

Desktop dotfiles ecosystem: the Quickshell (QML) Hyprland shell plus Hyprland, matugen and the apps around them. Every top-level directory is a stow package. This is a config repo, not a software project.

## There is no toolchain — do not look for one

- No `package.json`, build system, test runner, linter, formatter, typecheck, CI, pre-commit, or task runner exists. Nothing to "run".
- **Quickshell 0.3.2 is installed** (`qs --version`). The scaffold was written against 1.x, so most API names needed correcting — see the API section below. Verify against the installed version, not the README.
- The only real verification is `qs -p ~/.config/quickshell` (plain `qs` once stow-deployed). QML errors surface on load, so a clean launch is the smoke test.

## Deploying

One stow package per top-level directory; each package contains `.config/<app>/` (or a dotfile at its root). Deploy everything with the installer, or name packages to deploy a subset:

```bash
./install.sh                  # all 12 packages, dry-run + conflict backup first
./install.sh hypr quickshell  # just the named ones
```

- Packages: `quickshell`, `hypr`, `rofi`, `kitty`, `cava`, `swaync`, `btop`, `fastfetch`, `matugen`, `bash`, `zsh`, `OpenTabletDriver`.
- Conflicts (real files) are moved to `~/.dotfiles-backup-<timestamp>/` before stowing. Pre-existing **symlinks** are not backed up — remove them by hand first (that is how the `~/hypr-dotfiles` migration was done).
- Undo a single package with `stow --dir=. --target="$HOME" -D <pkg>`.
- **Never `stow .`** — the repo root is not a package. With 13 package dirs at the root it would try to link all of them straight into `$HOME`. Always name the package (or use `install.sh`).
- GNU Stow 2.4.1 verified. On stow < 2.4.0 the default ignore list drops `README.md`, which would land at `~/README.md` — check `stow --version` before running this elsewhere.

## Layout and real entrypoints

- `quickshell/.config/quickshell/shell.qml` is the only entrypoint (`ShellRoot`). One `PanelWindow` per monitor via `Variants { model: Quickshell.screens }`. The bar window is full-width but transparent; `Bar.qml` draws a centered pill inside it. The window reserves the pill's band via `exclusiveZone` (bound to `bar.barHeight + bar.topMargin`), so windows are pushed down while the pill still floats — drop `exclusionMode` entirely, since `ExclusionMode.Normal` is the default and what makes the reservation take effect.
- `Modules/Bar` (media / workspaces+clock / network+volume+memory+battery, plus a hover-expanded dynamic island: the pill never moves, a 600×450 (4:3, half the bar's width) media card pops open from the top center with its body a step lighter than the bar (`Theme.cardBackground`) and the menu column strip down the left edge keeping the bar's color, and each junction where the card's side edge meets the bar's bottom edge is smoothed by a tangent fillet in the pill's canvas that tracks the card's popped geometry through the animation; the card itself is a Canvas whose bottom-corner radius tracks its visible height, so its corners stay rounded through the whole pop instead of only at full expansion), `Modules/Launcher` (rofi drun replacement), and `Modules/Corners` (painted rounded screen corners) are live. `Modules/Notifications` (popup stack at the top right under the bar, replacing swaync's popups) is live; `Modules/OSD`, `Modules/Session` are still `visible: false` stubs whose intent lives in their `// TODO:` header comments.
- **The island has two pages, switched two ways.** A vertical tab column down the card's left edge — two 40×40 buttons flush against each other (no gaps) inside the bar-colored column strip — switches pages on click; the selected page takes the lime accent fill (square corners, `cardAccentOn` near-black glyph, and a thin black line down its left edge), the unselected one stays transparent. The clock zone opens the media page and the volume icon in the right row opens the volume page (per-app sliders, `Modules/Bar/VolumeCard.qml` — pavucontrol's playback tab in the shell's language) on hover. `islandPage` resets to media whenever the island collapses, so the clock never inherits a stale volume menu, and `hovered` gates each trigger on the current page so the card stays open while the cursor is on it either way. The column's block ends at x=56 (leftMargin 16 + 40 wide), and VolumeCard's content keeps a 64px left margin to clear it.
- **The card pops rather than swipes.** One `pop` progress value (0→1) drives the clip's height, the card's horizontal `Scale` (origin top-center), the pill's roll geometry and the window's mask together, so the card grows outward from the top center — height from the bar's bottom edge, width from the center line. `popIn` (380ms, `OutBack`) overshoots to ~1.1x for the pop; `popOut` (240ms, `OutCubic`) has no undershoot, so the card never dips below zero and mirrors on the way down. The overshoot needs headroom in two places: the clip runs `popOvershoot` (1.12) wider than the card, or the scaled card's side edges get shaved square against the clip, and `windowHeight` carries matching slack, or the window's bounds cut the overshoot off.
- `Services/` holds the data singletons the bar reads (`AppAudio`, `Audio`, `Media`, `Battery`, `Network`, `Memory`) plus `Matugen`. See the Services section below — the lazy-initialisation rule there is the thing most likely to bite.
- The other packages' entrypoints: `hypr/.config/hypr/hyprland.lua` (pure-Lua Hyprland config; requires `animations`, `effects`, `keybinds`), `matugen/.config/matugen/config.toml` (palette templates for hypr/rofi/kitty/cava/quickshell), and `rofi`/`swaync`, which the quickshell modules are replacing one by one.

## Theme singleton — the non-obvious part

- `Theme/qmldir` is what registers the singleton (`singleton Theme 1.0 Theme.qml`) and must also declare `Colors 1.0 Colors.qml`. From `shell.qml` you write `import "Theme"`; from `Modules/<Name>/` you need `import "../../Theme"` (see the import section below).
- `Theme.qml` and `Services/Matugen.qml` both use `pragma Singleton` with root type `Singleton` from `import Quickshell`. Follow that shape.
- `Theme/Colors.qml` holds raw hex values (catppuccin-mocha defaults) and is the file matugen is meant to overwrite. Hand-edits there will not survive a palette regeneration.
- **The bar palette deliberately does not live in `Colors.qml`.** `Theme.qml` carries `fixedBar*` constants plus a `barUseMatugen` switch and derived `bar*` properties. `Bar.qml` references only the derived ones, so flipping the bar between the fixed white pill and matugen colors is a one-line change in `Theme.qml`, not a bar rewrite. The fixed palette is white with near-black text — check contrast before lightening the text, since a white surface with the old light-gray text is unreadable. A TEMPORARY `Theme.darkMode` property (click the `//` prefix to flip) switches the fixed palette to a deep charcoal pill — the transport buttons and the island's tab column keep the inverted language via `barInk` (darker than the bar) with `barOnInk` labels; it moves to a proper menu later, and matugen still wins when `barUseMatugen` is on. The workspace pill flips with `darkMode` via `barWorkspacePill` — near-black ink in dark mode (the original inverted island), light gray in light mode — with the active circle taking `barBackground` (a shade lighter than the ink in dark mode, white in light mode) and a `barForeground` number, the one label color that reads on both fills; inactive numbers use `barWorkspaceDim` (the dark palette's muted gray, or a deeper gray that survives on the light surface).
- `Notifications`, `OSD`, and `Session` still hardcode `#1e1e2e` instead of referencing `Theme.barColor`. Replace those with `Theme` properties when fleshing the stubs out.

## Services — the lazy-initialisation trap

`Services/qmldir` declares each singleton the same way `Theme/qmldir` does. A qmldir singleton needs **both** the `Singleton` root type and a `pragma Singleton` line — either alone fails to load, and because a broken sibling takes the whole module down, one bad file surfaces as "Type Audio unavailable" for everything.

- **Quickshell initialises its services lazily.** `Mpris.players`, `UPower.devices`, `Hyprland.workspaces` and `Pipewire` all read as empty until something *observes* them. A `Connections { target: X; function onValuesChanged() {...} }` is what forces population — without one the model stays empty forever and the UI silently shows nothing. Every service wrapper in `Services/` carries one for this reason; it is load-bearing, not decorative.
- **Singletons instantiate lazily on first property access.** Referencing `Audio.volume` from inside a timer callback creates the instance at that moment, so its `Component.onCompleted` polling never gets a chance to run. Reference them from a binding that exists at load time (as `Bar.qml`'s text bindings do), not from a deferred callback.
- **`NotificationServer` is NOT a qml singleton in 0.3.2, whatever the docs suggest.** The shipped qmltypes carries no `isSingleton` flag, so bare `NotificationServer.trackedNotifications` reads `undefined` — silently, with no type error — and nothing ever claims `org.freedesktop.Notifications`. It must be instantiated as an object (`NotificationServer { id: notificationServer }`); that instantiation is what registers the dbus service. Verified by probe: bare access → `undefined`, object → name registered. Set `keepOnReload: true` on it to keep the stack across hot reloads, and advertise capabilities (`bodySupported`, `actionsSupported`, `imageSupported`, …) or apps degrade to plain text. Note swaync's `/usr/lib/systemd/user/swaync.service` is dbus-activated on the same name, so while swaync is installed every `notify-send` resurrects it — retiring swaync means killing the autostart AND removing the package.
- **A `NotificationServer` silently discards every notification unless a handler marks it tracked.** `Notify()` emits the `notification` signal and then checks `isTracked()` — an untracked notification is deleted on the spot and never enters `trackedNotifications`. The server owns the dbus name, `notify-send` exits 0, and the stack stays empty with zero errors anywhere: the only fix is `onNotification: (notification) => notification.tracked = true` on the server object. (Source: `NotificationServer::Notify` in 0.3.2 — `if (!notification->isTracked()) { …delete… }`.) This is why SUPER+N "didn't work" for a full debugging round: the bind, the command and the dbus path were all fine.
- **A `ListView` whose height binds to its own `contentHeight` never renders anything.** It starts at zero, a zero-height view instantiates no delegates, and with no delegates the content can never grow — the model populates, the signal fires, the screen stays empty. Give the view a height independent of its content (the window's band) and let the *wrapper* track `contentHeight`, which is what the input mask should follow anyway.
- **`modelData` is context-resolved and nulls the instant an item leaves the model.** A delegate outlives its model item by the exit animation, so any binding to `modelData` reads null on the fading card and floods the log with TypeErrors. Capture once instead — `property var notification: null; Component.onCompleted: notification = modelData` — and pair it with a `RetainableLock { object: …; locked: true }` so the underlying object (Notification is `Retainable`) survives until the card is destroyed. Without the lock the captured pointer dies with the model removal; without the capture the lock is useless.
- **`Quickshell.iconPath("")` mangles into a broken request.** An empty icon name produces `"?fallback=…"` as the image source and logs a load failure per size — guard the call (`appIcon.length > 0 ? iconPath(…) : ""`) when the sender may omit an icon, as `notify-send` does. Named-but-missing icons (`preferences-system-network`, `hwloc` in the launcher) warn the same way and are harmless.
- **`Pipewire` is unusable for sink volume here.** The default sink node stays `ready: false`, so `sink.audio.volume` reads 0 while `wpctl get-volume` reports the truth. `Services/Audio.qml` polls `wpctl` instead — read via `get-volume`, write via `set-volume`/`set-mute`, and re-read in `onExited` so the UI never shows a stale value.
- **Per-app volume goes through `pactl`, not the Pipewire service** (same reason as above). `Services/AppAudio.qml` polls `pactl list sink-inputs` every 2s — each stream's id, `application.name`, first-channel percentage and mute state — and writes via `set-sink-input-volume` / `set-sink-input-mute`. Two traps found while building it: writes must go through a **one-deep queue drained by the process's own exit**, because `running = true` on an already-running Process is a silent no-op and a slider drag would drop every write but the first; and the volume rows keep a **local visual value while dragging**, because the 2s poll read-back landing mid-drag snaps the handle back to the old value. Commits throttle to one per 100ms so the audio follows the drag live without a pactl per mouse-move.
- **`Networking` returns nothing here** — zero devices and `wifiEnabled: false` while NetworkManager is active and connected. `Services/Network.qml` polls `nmcli` instead: `device status` decides connectivity and medium, then `device wifi` adds signal strength.
- **No service covers memory.** `Services/Memory.qml` parses `/proc/meminfo`, using `MemAvailable` rather than `MemFree` as the basis for "used".
- `UPower.displayDevice` can report `ready: false` with a zero percentage until the device list is enumerated, so `Battery.qml` prefers the real `isLaptopBattery` device from `UPower.devices` and only falls back to `displayDevice`.
- Reading a `Process`'s output: attach a `StdioCollector` to `stdout` and handle `onStreamFinished`, where `this.text` holds the whole output. `waitForEnd` is not needed for short-lived commands.

## Working agreement

- **Never drive the user's input.** No synthetic keyboard/mouse via `/dev/uinput`, no screenshots to verify interactive behaviour. Inputs and clicks are the user's to test.
- **Verification is a separate phase.** When something needs checking, do it in a clearly separated troubleshooting step — not interleaved with implementation edits. Inline load checks (`qs -p ~/.config/quickshell` starts clean) are fine.
- **All config lives here.** Hyprland, matugen, rofi — everything is a package in this repo now. The old `~/hypr-dotfiles` repo is a read-only archive until burn-in passes; never edit it.

## Quickshell API — verified against 0.3.2, not the 1.x scaffold

The Arch `*.qmltypes` files are **stale** (the Hyprland one is an empty stub). Trust runtime probes, not typeinfo. Verified facts:

- `Process.command` takes a **QStringList**, not a string. A plain string becomes a single argv element and fails to start. `Services/Matugen.qml`'s list form is correct.
- `DesktopEntry.command` is a **QStringList** (stringifies comma-joined). Pass it straight to `Process.command`; field codes like `%U` are already stripped.
- `DesktopEntries.applications` is an `UntypedObjectModel`. Read it as **`.values`** (a JS array), and wait for the **`applicationsChanged`** signal — it is empty at `Component.onCompleted` time. Same pattern for `Hyprland.workspaces.values`.
- **Services initialise lazily and stay empty until observed.** See the Services section — this is the single most common cause of a silently blank widget.
- `Hyprland.workspaces` carries the special workspace (`id === -98`) and is unordered. Filter to `id > 0` and sort before rendering.
- **`Hyprland.dispatch(request)` interpolates the request raw into a Lua call** (`return hl.dispatch(<request>)`), and this machine's Hyprland runs a Lua config. The legacy string form `"workspace N"` dies with a Lua syntax error (`')' expected near '1'`), and the quoted form `"'workspace N'"` dies with `expected a dispatcher`. The working request is a real dispatcher object: **`Hyprland.dispatch("hl.dsp.focus({workspace = " + id + "})")`** — confirmed switching *and* creating missing workspaces. `hyprctl dispatch workspace N` from the shell hits the same Lua wrapper and fails identically, so a `Process` fallback is not a way out. Native `workspace.activate()` also works, but only for workspaces that already exist (useless for the bar's persistent 1–4 placeholders). Dispatcher syntax ground truth is `hypr/.config/hypr/keybinds.lua` in this repo (workspace switching is `hl.dsp.focus({ workspace = i })`; `hl.dsp.workspace` is a table, not callable). Note: `Hyprland.workspaces`' `valuesChanged` does **not** fire when only the active flag changes — verify switches with `hyprctl activeworkspace`, not with the model signal.
- `Mpris` player fields are `trackTitle` / `trackArtist` / `trackArtUrl` — there are no plain `title` / `artist` properties, and they read `undefined` until a track is loaded.
- `Quickshell.screens` is a JS-array-like list; use `.length` / `[i]`, not `.count`.
- `Quickshell.env()` is a **method**, not a property.
- `Timer` and `Component` need an explicit `import QtQml` — `import Quickshell` alone does not provide them.
- `PanelWindow`: use `implicitHeight`, not `height` (the latter is deprecated and warns). `exclusiveZone` and `ExclusionMode.Ignore` both exist.
- **`WlrLayershell` needs `import Quickshell.Wayland`.** The attached object (`WlrLayershell.layer: WlrLayershell.Overlay`) resolves only with that import — without it the config dies with "Non-existent attached object" at the assignment. Layer enum is `Background / Bottom / Top / Overlay`. Corners and the notification popups both sit at Overlay, so they show above fullscreen windows — that is the point of the trick, and also its cost. **Property syntax only, never an attached-object block:** `WlrLayershell { layer: ... }` loads clean in 0.3.2 but leaves the window at Top *and* spawns a stray default-sized (100×100) Overlay surface that hyprland centers in the workarea — a white square mid-screen owned by nothing in the QML. Bisected with throwaway probe configs (block → stray square, property → one clean surface) before touching the live module; the notifications module shipped with the block and wore the square until it was caught.
- **Nothing rounds the physical screen.** `Modules/Corners` paints four corner cutouts (a `Canvas` path per corner: square minus quarter-disc) in `Theme.screenCornerColor` at the Overlay layer, with `ExclusionMode.Ignore` so the monitor's reserved area is untouched. Fullscreen content loses its corner pixels and the color must match the wallpaper to blend — both inherent to the approach. Off switch is `Theme.screenCornersEnabled`.
- **A full-screen layer surface eats all input unless masked.** A `PanelWindow` covering the whole monitor accepts clicks and scrolls across its entire extent (layer-shell input region defaults to the whole surface) — a transparent click-through overlay is *not* the default. `PanelWindow.mask` (a `Region`, default property `regions`, `intersection: Intersection.Combine` to union children) clips rendering **and** input: only the masked area is clickable, everything else passes through. Region items carry `x/y/width/height` plus per-corner radii (`topLeftRadius` etc.), so a mask can match a rounded cutout exactly. `Modules/Corners` sets one to its four cutouts; without it the desktop goes dead the moment the shell loads. If input ever dies after a shell change, `pkill -f 'qs -p'` is the instant recovery.
- **A mask can track an item live.** `Region { item: someItem; radius: someItem.radius }` follows the item's geometry and corner radius through animations — `PendingRegion` connects every geometry property to a `changed()` signal, and `ProxyWindowBase` re-applies the mask on polish. Regions nest: `regions` is the default property, `Intersection.Combine` is the default intersection, and a child's `item` overrides its own x/y/width/height. This is what lets the bar window be *taller than its exclusive zone* (the island card pops open past the reserved band) without the extra area swallowing clicks: `shell.qml` points the bar's mask at a pill region with a nested card region, and both are explicit geometry. The pill's because its canvas is taller than the bar by the roll's depth, and an item-based region would cover that strip and swallow clicks below the bar's edge — so it pins `x/y/width` to `pillItem` with `height: bar.barHeight` and the four corner radii bound to `pillItem.radius`. The card's because the card pops open *scaled* and a Region tracks an item's geometry, never its transform — an `item:`-based region would sit at full width through the whole pop and swallow clicks beside the animating card — so it binds `x` to the popped width centered under the pill, `y` to `cardItem.y`, and `width`/`height` to `cardWidth * pop` / `(cardHeight + cardRadius) * pop`, making the region the visible card at every frame and nothing at all when collapsed. If the child region ever fails to register, the failure mode is safe — only the card's clicks die, the bar keeps working. Coordinates are logical, not device pixels.
- **A `MouseArea` only accepts hover events when `hoverEnabled` is true.** A non-hover MouseArea stacked above a hover one does not steal `containsMouse` — that is what lets the island's hover trigger sit *under* the media card's buttons and stay hovered while the cursor is on them. (`QQuickMouseArea::setHoverEnabled` calls `setAcceptHoverEvents(h && enabled)`.)
- **The pill is a `Canvas`, not a `Rectangle`** — the island's junction needs the bar's bottom edge to roll where the card emerges, and a Rectangle's outline is fixed. The card's side edges meet the bar's bottom edge at a hard 270° corner; the roll replaces it with a tangent fillet per side — one arc, tangent to the bottom edge (horizontal) where it leaves it and tangent to the card's side edge (vertical) where it lands, centered in the empty region outside the corner. It is material-growing, not a bite: no gap opens, and the card's tucked corners stay hidden behind the roll — which is why the smoothing lives on the pill and not on the card. The canvas is `barHeight + cardRadius` tall because the rolls hang below the bottom edge and a Canvas clips its painting to its own bounds; the extra strip is transparent except for the rolls, and shell.qml's mask pins the pill's input region to the bar's own 36px band so the strip never swallows clicks. Traversal (bottom edge R→L, `bh = root.barHeight` — not the canvas height): right roll is `lineTo(cx+fr, bh)` → `arc(cx+fr, bh+fr, fr, -π/2, -π, true)` → `lineTo(cx, bh)`; left roll is `lineTo(nx, bh)` → `lineTo(nx, bh+fr)` → `arc(nx-fr, bh+fr, fr, 0, -π/2, true)`. The corner where each detour rejoins the bottom edge is interior — the card's material fills it — so only the arc and the card's edge form the visible boundary. The roll's radius is neither a constant nor tied to `expanded`: it tracks the card's visible overhang minus whatever the card's own bottom corner is rounding off — `over = cardClip.height - cardRadius; rb = min(cardRadius, max(0, over/2)); fr = clamp(over - rb * pop, 0, cardRadius)` (the `rb * pop` because the card's painted corner radius is rb scaled by the pop) — so the roll's tip lands exactly where the card's corner arc begins at every height, both curves tangent-vertical there, and the junction reads as one smooth S with no gap and no detached tab through the whole pop in both directions. The rolls also sit at the card's *popped* width: `nx`/`cx` come from `cardWidth * pop`, not the resting width. Tying the roll to the boolean instead pops the rolls off the instant a collapse starts, leaving the sharp corner bare for the full 240ms the card takes to retreat. The card is a `Canvas` for the same class of reason: its bottom corners must stay rounded through the pop, and a Rectangle's radius is fixed — a 24px corner on a card the clip has not finished revealing reads as a clipped square, so the rounding only appears once the card is fully open. The card's canvas fills the clip's height and is centered in it at the resting `cardWidth` (the clip runs `popOvershoot` wider to leave the overshoot room), with a `Scale` transform (origin top-center, `xScale: pop`) doing the horizontal pop; it repaints every frame via a `Connections` on `cardClip.heightChanged`, paints the rounded rect with the top corners at `cardRadius` — hidden behind the bar — and the bottom corners at `rb = min(cardRadius, max(0, (height - cardRadius)/2))`: full radius once the visible band can hold one, a semicircular cap while it is shorter, zero before the card clears the bar's bottom edge. The card body is `Theme.cardBackground`, a step lighter than the bar; after the fill it paints the menu column strip down the left edge back in `barBackground`: the outline path is still current after `ctx.fill()`, so `ctx.save()` → `ctx.clip()` → `fillRect(0, 0, cardColumnWidth, h)` → `ctx.restore()` hands the strip the card's own rounded left corners for free (its right edge stays square against the card), and it scales with the pop like everything else on the canvas. The repaint `Connections` watches both `barBackgroundChanged` and `cardBackgroundChanged`, so a matugen regeneration repaints either half. The content Item stays a child of the canvas and renders above the paint. Three details bite: `Canvas` has no `radius` property, so the pill declares its own `readonly property real radius` for the mask; repaints must be requested explicitly (a `Connections` on `cardClip.heightChanged` drives the per-frame pop repaint, plus a `Connections` on `Theme.barBackgroundChanged` for matugen regenerations); and every `ctx.arc` must start at the point the path is already standing on, or canvas silently inserts a straight connector and the curve collapses (Corners.qml learned this the hard way).
- **`getImageData` reads the DPR-scaled backing store, not logical pixels.** On this monitor (scale 1.6) a sample at logical (400,34) actually reads logical (250,21) — verified by sampling the pill's rounded caps (opaque inside the curve, transparent outside). When probing Canvas output, multiply logical coordinates by the device pixel ratio first. This is how the roll shape was verified without a screenshot: alpha runs along rows below the bottom edge reconstruct each fillet (`.0-293 O294-299 .300-899 O900-906 .909-1199` at y40 when fully expanded — two tapering bumps at the card's edges, nothing between them; the body rows unchanged; all transparent when collapsed). Driving `cardClip.height` to exact mid-pop values verifies the tracking: at height 30 (fr=6, rb=6) the roll's body shows at y38 (`.0-298 O299-299 .300-899 O900-901`) while the tip rows y40/y42 fall below the alpha threshold — a 6px fillet is a hairline there — and the card's own corner arc starts at card-local 24 (full width, `O0-599`) and curves by local 26 (`.0-0 O1-599`, left boundary 0.34, right 599.66); at height 40 (fr=11, rb=11) the roll shows at y42 (`O900-901`), tips at y44 (`O900-900`) and vanishes by y47, with the card full width at local 29 and curving at local 31. The roll's tip row always equals the card's arc-start row (42 at height 30, 47 at height 40) — that equality is the junction check. Fully expanded, the card's bottom corner is the exact r24 quarter circle (all probed values in this paragraph were taken at the original 18px radius): `.0-0 O1-599` at card-local 455 and `.0-6 O7-593` at 464. Five probe gotchas: `Canvas.canvasSize` reports the *logical* size (1200×54) while the store is device-scaled (1920×86.4), so derive the scale from the monitor, not from `canvasSize`; `getImageData` does not clamp out-of-bounds requests — it returns the requested size filled with transparent, so a clamp-probe of the store size silently lies; `Screen.devicePixelRatio` reports 2 on this monitor while the real output scale is 1.6 — trust the cap-edge arithmetic, not the property; `getImageData` sees only the canvas's own paint — child items (the card's art/text/transport, the pill's topBand) render above the canvas texture in the scene graph and never appear in the store, so probing a child's pixel reads the canvas underneath (this is why the play button probed white); and driving `cardClip.height` from JS fights the `pop`-derived binding — the assignment sticks until the next animation frame re-asserts it, so pin it with `cardClip.height = Qt.binding(function () { return N })` (or stop the pop animations and set `pop` directly) when a probe needs a value to hold.
- **The bar hides itself over fullscreen windows — that is Hyprland, not a bug.** `CLayerSurface::onCommit()` (src/desktop/view/LayerSurface.cpp, Hyprland 0.56.2) sets the alpha *goal* to 0 for every layer below Overlay while the monitor has a fullscreen window; Overlay layers keep goal 1. `hyprctl -j layers`' per-layer `alpha` field is that goal, so a fullscreen game/video reads bar 0 + corners 1 — expected, and nothing is wrong with the QML. Check `hyprctl -j clients` for a `fullscreen` client before investigating an invisible bar. (This repo went down a long rabbit hole blaming hot reloads and launch paths for alpha 0 — all of it was osu! running fullscreen.)
- **That goal is only re-evaluated when the layer surface itself commits** (a `wl_surface.commit` from quickshell: clock tick, hover, media change, workspace switch). `arrangeLayersForMonitor` does not touch alpha, so after fullscreen exits the bar can stay invisible until its next commit — up to ~60s with the minute-precision clock, or instantly on any interaction. If the recovery lag ever matters, the fix is a client-side keep-alive commit (something visible changing every second), not a config change.
- **Children of a `PanelWindow` do not auto-fill its content item.** A plain `Item` declared inside one stays 0x0 unless it sets `anchors.fill: parent` (or explicit width/height). Anchors that reference `parent` then resolve against a zero-size parent — `horizontalCenter` parks the child at negative x, half off-screen. `Launcher.qml` sidesteps this by making the `PanelWindow` itself the component root; `Bar.qml` uses `anchors.fill: parent`. Verify any new module's root geometry at runtime before trusting it.
- `SystemClock.Seconds` and `Variants` both exist as the scaffold uses them.
- **Tray menus need `//@ pragma UseQApplication`.** `SystemTrayItem.display()` renders through Qt's platform-menu layer, which only exists when quickshell runs as QApplication — without the pragma (first line of `shell.qml`) every right-click logs `Cannot display PlatformMenuEntry as quickshell was not started in QApplication mode` and no menu appears. The pragma is read at startup only: a hot reload does not apply it, a full restart does.
- **There is no reload path except a restart.** `qs` has no reload subcommand (`log`/`list`/`kill`/`ipc`/`msg` only), and the file watcher ignores mtime-only changes — `touch shell.qml` does nothing, only content edits reload. SUPER+R therefore runs `pkill -x qs; sleep 1; qs` (`hypr/.config/hypr/keybinds.lua`); the relaunch inherits `WAYLAND_DISPLAY`/`XDG_RUNTIME_DIR` from hyprland's exec environment, the same path the autostart uses, and the sleep keeps the dying instance from briefly double-drawing the bar.

## QML import rules that bite here

- From `Modules/<Name>/<Name>.qml`, the Theme import is **`import "../../Theme"`** — two levels up. `../Theme` silently resolves to the nonexistent `Modules/Theme`.
- Every module directory needs its own `import "Modules/<Name>"` line in `shell.qml`; QML does not propagate imports.
- A directory containing a `qmldir` does **not** implicitly expose its sibling files as types. `Theme/qmldir` must declare `Colors 1.0 Colors.qml` or `Theme.qml`'s `Colors {}` reference fails with "Colors is not a type".
- `Launcher` must be instantiated once in `ShellRoot`, **not** inside the per-monitor `Variants` delegate (a `Component` accepts only one root object).

## Launcher

- `Modules/Launcher/Launcher.qml` replaces rofi drun. Toggle from Hyprland with `qs ipc call launcher toggle` (also `open` / `close`).
- TextInput → filter must use `onTextEdited: root.filter = input.text`. A `text: root.filter` binding is one-way and breaks on the first keystroke, so the list never filters.
- Keyboard: Up/Down wrap (rofi's `cycle: true`), Enter launches, Escape closes. Click outside the card dismisses; clicks on the card are swallowed by a `MouseArea`.
- Metrics mirror rofi's `config.rasi`: 500px card, radius 22, 7 visible rows, radius 12 selection, 30px icons.
- The launcher references only the derived `bar*` palette properties (`barBackground`, `barHighlight`, `barForeground`, `barDim`, `barInk`, `barOnInk`) — never the raw semantic ones (`barColor`, `surface`, `text`, `muted`, `accent`), which read `Colors.qml` and ignore `darkMode`. It shipped once on the raw palette and rendered a catppuccin card under the fixed pills. The selection row uses `barInk`/`barOnInk`, the same inverted language as the workspace pill.

## Icons

- **Status icons are Nerd Font glyphs, not images.** `Theme.iconFont` is `"JetBrainsMonoNL Nerd Font"` (verified to cover Font Awesome `f000–f381` and Material `f0001–f1af0`). It is set explicitly on each glyph `Text` — the bar's UI font is not an NF family, so inheriting it renders every glyph as tofu. The bar's status readouts (network, volume, battery) are icon-only: state rides the glyph tier (ban/wifi/globe, speaker-off/down/up, bolt/tiered cells) plus the palette color, with no value text — the SSID and percentages were deliberately dropped. Because the glyph is text it inherits `color` and follows the palette/dark toggle for free.
- **Do not use SVG for status icons.** Qt's SVG renderer (`libqsvg.so`, installed) draws symbolic SVGs as authored and does not resolve `currentColor`, so the fill is baked in — one color cannot serve both the light and dark pills. SVG app icons in the launcher are fine precisely because brand color is the point there.
- **Launcher app icons stay `Quickshell.iconPath` + `Image`** (`sourceSize` 30; bump to 48 if they ever look soft at the 1.6 DPR). `Quickshell.Widgets.IconImage` is a thin `Image` wrapper — same loader, icon-sane defaults, no SVG magic. Themeable-vector fallback if ever needed: `Shape` + `PathSVG`.
- **Glyph coverage is per-codepoint, not per-range.** `F538` (md-memory) sits in the gap *between* the FA and Material blocks — not inside either — and renders as tofu (it shipped once as the memory icon before that readout was removed). Verify any new glyph against the font before shipping it: `fc-query -f '%{charset}\n' <font-file>` lists the covered ranges, and a codepoint is only safe inside one of them.
